# 地端設備架構規劃（辦公室小主機 + 抽取盒陣列）

> 本文檔為**規劃層級**：架構圖、採購清單、關鍵決策。
> 不含逐條安裝指令；實作細節請參考同倉的
> [NAS 部署指引](nas-deployment-guide.md) 與 [外網連線指引](external-access-guide.md)。

---

## 一、目標

在辦公室用一台**小主機**當伺服器，**外接硬碟抽取盒**，把公司的
**內控系統 + 公司網站 + 資料庫**全部在地端設備上運行，不依賴公有雲。

核心精神：**資料留在自己辦公室、可控、可備份、不上公雲**。

---

## 二、架構圖

```

   員工 (內網)          │   辦公室路由器 / 防火牆       │   員工 (外網, 可選)

                        │   小主機 (Ubuntu Server)      │
                        │   ┌───────────────────────┐  │
                        │   │ Docker Engine          │  │
                        │   │  ├─ caddy     (反向代理 │  │
                        │   │  │             + 自動HTTPS)
                        │   │  ├─ controlflow (內控系統)│ │
                        │   │  ├─ website     (公司網站)│ │
```

## 三、採購清單（建議）

| 項目 | 建議規格 | 用途 | 優先級 |
|------|----------|------|--------|
| 小主機 | 迷你 PC（N100 / N305 / i3），4 核以上，16GB RAM | 跑 Docker 與所有服務 | 必備 |
| 系統碟 | 256–512GB SATA/NVMe SSD | 裝 OS + Docker 映像 | 必備 |
| 資料碟 | 2–4TB HDD ×2（做 RAID1 鏡像）或 ×1 + 1 備份碟 | 放 DB / 附件 / 網站檔 | 必備 |
| 抽取盒 | **多槽、獨立電源、能讓 OS 個別辨識每顆碟**的型號（USB3 / eSATA） | 陣列或輪替冷備 | 必備 |
| UPS | 入門塔式（500–1000VA） | 防雷防瞬斷，避免 DB 損毀 | 強烈建議 |
| 網路 | 現有路由器即可；預算夠可上 2.5G 交換器 | 員工內網存取 | 選配 |
| 網域 | 申請一個公司網域（如 company.com.tw） | 對外 HTTPS 憑證需要 | 若要外網則必備 |

> 抽取盒選購要點：**不要**買「盒內做死硬體 RAID 且封閉」的款式；
> 選能讓 Linux 看到每顆獨立碟的，才能用軟體 RAID（mdadm/ZFS）或當輪替冷備碟。

## 四、關鍵決策

### 1. 作業系統：Ubuntu Server 22.04 LTS
免費、文件多、Docker 支援好。不用桌面版。

### 2. 一切容器化
內控系統已提供 `Dockerfile` + `docker-compose.yml`。
公司網站、資料庫、反向代理都跑容器，便於遷移與重建。

### 3. 資料庫：SQLite 先、PostgreSQL 後
- **現階段**（只有內控、人數 < 50）：SQLite 單檔夠用，`config.py` 已預留
  `DATABASE_URL` 切換，未來無痛換。
- **規模上來 / 多服務共用 / 外網並發**：把內控系統改連 **PostgreSQL**
  （同主機一個 `postgres` 容器，多服務共用）。不建議現在就過度工程。

### 4. 「陣列」怎麼做（兩選一，不互斥）
- **RAID1 鏡像（雙碟）**：防「一顆碟掛掉服務不中斷」。用軟體 RAID（mdadm/ZFS）。
- **抽取碟輪替冷備**：每天備份到一顆可抽出的碟，輪流帶走/離線。防勒索病毒、誤刪、火災。
- **結論**：兩者都要最好；至少要有其一。**RAID ≠ 備份**，兩者目的不同。

### 5. 備份策略：3-2-1
- 3 份資料：線上資料碟 + 抽取冷備碟 + Mage20 Pro
- 2 種媒體：HDD + NAS
- 1 份離線：抽取碟輪替（防勒索）
- 每日自動備份；定期抽驗還原。

### 6. 對外連線（若需要）
參考 external-access-guide：小主機前放 **Caddy** 做反向代理 + 自動 HTTPS；
**不要**直接裸露容器埠。內網先跑、確認穩定再考慮開外網。

### 7. 安全清單（上線前）
- 改預設 admin 密碼、為每位員建專屬帳號與角色
- `SECRET_KEY` 用環境變數、強隨機值
- 只開必要埠（443）；路由/防火牆擋其餘
- `.gitignore` 已排除 `app.db` / `uploads` / `.env`，公司資料不上倉庫
- 啟用 UPS，避免斷電損毀 SQLite/PostgreSQL

---

## 五、落地路徑（MVP → 完整）

1. **MVP**：小主機 + SSD + 單資料碟 → Ubuntu + Docker → 內控系統容器跑起來（內網）。
2. **加備份**：抽取碟每日備份 + Mage20 Pro 同步。
3. **加陣列**：資料碟升級 RAID1（或加冷備輪替）。
4. **加網站/DB**：公司網站容器、必要時 PostgreSQL。
5. **加對外**：Caddy + HTTPS + 防火牆（若需外網）。

---

## 六、注意事項
- 這套是**地端自管**，意味著「可用性」與「備份」由公司自己負責：
  停電、主機故障、被盜都要有對策（UPS + 備份 + 異地）。
- 若日後公司成長，可把同套 Docker Compose 平滑搬到更強的主機或支援
  Docker 的 NAS，資料卷一併搬移即可。
